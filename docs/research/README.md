# AI 策略研究协议

本目录用于保存 AI 自动研究闭环的公共上下文和每一轮独立研究记录。目标是让每次策略制定都可复现、可比较、可传递给下一轮，而不是散落在聊天记录里。

## 固定目标

长期北极星目标和完整阶段路线见 `long-term-goal.md`：年化收益率 `>= 100%`、最大回撤绝对值 `< 10%`、已完成交易盈亏比 `>= 3:1`。当前不会把这一目标直接套到所有历史结果上，而是按 `stages/` 目录逐阶段推进。

第一阶段单票扫描目标：

- 三年区间总收益率 `>= 20%`。
- 最大回撤绝对值 `<= 15%`。
- 单票研究至少 `3` 笔完成交易。
- 纪律评分、胜率、交易数作为诊断指标；默认不作为收益/回撤目标的硬门槛，除非某轮研究明确提高约束。
- 新闻只作为解释和风险标签，不作为核心买入信号。

第二阶段策略进化后的全市场复核目标：

- 每完成一次策略进化，都必须跑三年全市场回测复核。
- 2026-05-31 起，合格研究级组合候选的收益目标提高为年化收益 `>= 30%`；三年窗口折算总收益约 `>= 119.70%`。此前“三年总收益 `>= 30%`”只作为历史可比口径保留。
- 单标的/成交标的风险线：已完成交易盈亏比 `>= 2:1`，最大回撤绝对值 `<= 10%`，尾部后 10 的亏损和回撤必须受控。
- 全市场复核必须记录候选数、测试数、跳过数、失败数、达标样本数、收益前 10、收益后 10 和失败原因。
- 收益后 10 是硬约束，不是展示项；其最差收益、最深回撤和最低盈亏比必须同时受控，不能只因为头部样本好看就判定策略达标。
- 组合级共享资金回测仍是后续增强；在它完成前，不要把逐标的全市场扫描说成组合收益。

默认入池过滤：

- 排除 ST / *ST。
- 排除北交所标的。
- 回测开始日前至少上市 `365` 天。
- 三年平均成交额 `daily.amount >= 100000`，单位沿用 Tushare 原始口径：千元，约等于日均成交额 1 亿元。
- 三年平均流通市值 `daily_basic.circ_mv >= 300000`，单位沿用 Tushare 原始口径：万元，约等于 30 亿元。
- 三年平均自由流通换手率 `turnover_rate_f >= 0.5`。

当前后端的全市场验证是“逐标的单票回测扫描”。它适合作为策略进化后的市场覆盖复核，但不能直接等同于共享资金组合策略。

## 单次研究文件夹

每轮研究必须独立成目录，至少包含：

- `hypothesis.md`：本轮假设、成功标准、失败条件。
- `context.json`：本轮使用的研究上下文快照。
- `strategies.json`：本轮实际验证的策略配置。
- `results.json`：API 返回的原始结果和筛选后的合格样本。
- `review.md`：本轮复盘、证据、局限和下一轮建议。
- `next-input.md`：供下一轮策略制定直接读取的简短结论。

## 执行方式

使用本地 API 跑研究：

```powershell
python scripts\research\run_research_round.py --run-id 001-baseline-boll-rebound --strategy boll-rebound
```

脚本默认读取 `docs/research/context.default.json`，调用 `http://localhost:18000`，并把结果写入 `docs/research/runs/<run_id>/`。

如果需要降低首轮成本或先做小样本试跑，可以传：

```powershell
python scripts\research\run_research_round.py --run-id 000-smoke --strategy boll-rebound --max-stocks 100
```

正式研究不要因为小样本达标就宣称策略成立。小样本只能作为调试和候选筛选。

组合诊断使用共享资金回测脚本。该脚本需要后端容器里的数据库依赖，推荐在 `api` 容器内运行：

```powershell
docker compose exec -T api python scripts/research/run_portfolio_backtest.py --run-id 014-portfolio-diagnostic --strategy trend-follow-maximum-profit-no-macd --source-run 010-filtered-universe-tail-audit
```

组合诊断会记录组合总收益、年化收益、最大回撤、盈亏比、交易次数、最大同时持仓、单票集中度和行业集中度。若逐标的尾部审计未通过，组合诊断只能作为失败证据，不能作为策略落地完成证据。

组合诊断默认启用市场宽度过滤：以前一交易日入池标的中站上 MA20、站上 MA60 和上涨占比判断是否允许新开仓。它还可以设置 `maxSignalScore`，用于过滤过热或过度放量的追高信号。所有这些参数都必须写入对应 run 的 `context.json` 和 `strategies.json`。

如果组合诊断使用了动态市场状态，逐标的全市场审计也必须同步同一批 `allowedEntryDates` 和入场质量阈值。不同口径的逐标的审计不能作为组合完成门槛的前置证据。

## 当前失败结论

截至 `046-portfolio-cross-section-strength-liquid-14pct-cool5`，`横截面择强 + 失败节流` 已经让组合级核心指标首次过线：三年总收益约 `32.68%`，年化约 `9.89%`，最大回撤约 `-9.95%`，组合盈亏比约 `4.00:1`，完成交易 `136` 笔，最大单票暴露约 `14.93%`，最大行业暴露约 `34.01%`。

但策略仍不能判定完成：逐标的源审计 `037` 未通过；组合实际成交标的后 10 的亏损和回撤已经压进 10%，但最低单标的盈亏比仍为 `0.00:1`。下一轮默认方向是“尾部盈亏比修复”，不要再单纯调止盈/止损。

`047` 至 `049` 已证明三个方向无效：减少每周交易会让收益不足；首亏后恢复会放大连续亏损；限制活跃标的名单会提高复用但显著恶化收益和回撤。下一轮应在买入前过滤“一笔止损型尾部”，例如加入止损前二次确认、开仓当日波动/缺口过滤、或对高分但高波动信号降权。

`050` 至 `053` 证明买入前风险过滤有效。当前最强前沿是 `053`：总收益约 `72.68%`，年化约 `19.99%`，最大回撤约 `-3.86%`，组合盈亏比约 `4.00:1`，最大单票暴露约 `14.90%`，最大行业暴露约 `27.30%`。`053` 将尾部审计拆开后确认：成交标的后 10 的亏损/回撤已通过，最差约 `-5%`；但盈亏比证据未通过，因为后 10 全部是 1 笔小止损，合格样本为 `0/10`。

`054` 至 `060` 继续验证了三件事：第一，单独压缺口或上影线只会降低收益，不能修复尾部盈亏比样本；第二，进一步提高流动性和市值门槛可以保留部分组合核心指标，但仍不能让后 10 自然产生足够复用；第三，把 `risk8` 同步到逐标的全市场源审计后，单票最高收益只有约 `22.26%`，说明当前策略的收益来自横截面组合轮动，最终落地门槛应以共享资金组合和成交标的尾部审计为主。

`061` 将目标硬门槛和诊断项拆开后，`cross-section-strength-risk8` 成为当前可执行组合策略基线：目标硬门槛全部通过，严格诊断项仍保留为后续优化方向。策略规格见 `executable-strategy-cross-section-risk8.md` 和 `executable-strategy-cross-section-risk8.json`。

`062` 至 `066` 将风险调整指标和成本敏感性纳入基线。`062` 复跑原始 14% 建仓上限后，三年组合总收益约 `72.68%`，年化约 `19.99%`，年化波动约 `8.26%`，Sharpe 约 `2.42`，Sortino 约 `5.62`，Calmar 约 `5.18`。`063` 使用 2 倍佣金和 2 倍印花税，收益和回撤仍过线，但最大单票暴露漂到约 `15.10%`，集中度门槛失败。`064` 把单票建仓上限降到 `13.5%` 后，2 倍成本压力下目标硬门槛重新全部通过：总收益约 `65.63%`，最大回撤约 `-3.81%`，Sharpe 约 `2.32`。`065` 验证正常成本下 `13.5%` 建仓上限也通过：总收益约 `70.12%`，最大回撤约 `-3.75%`，Sharpe 约 `2.44`。`066` 进一步验证 3 倍成本压力仍通过：总收益约 `62.05%`，最大回撤约 `-3.86%`，Sharpe 约 `2.22`。因此当前可执行基线更新为 `13.5%` 建仓上限；后续默认以 `065` 为正常成本基线，以 `064/066` 为成本压力证据。

`067` 至 `070` 加入滚动窗口验证和市场宽度诊断。最终口径 `070` 使用最多 3 个月历史数据预热指标，但只在窗口开始日之后交易和计绩；7 个年度/18 个月窗口中通过 5 个，失败 2 个。失败窗口为 `Y1` 和 `R18-1`，两者年化收益、Sharpe 和交易数均为 0，直接原因是窗口候选数只有 `739/846`，低于市场宽度过滤 `minSamples=1000`，导致 Risk-On 天数为 0。结论：不要先调止盈止损；下一轮应优先把市场宽度样本从交易候选池中解耦，避免候选集规模影响市场状态判断。

`071` 至 `074` 修正了市场宽度样本口径：交易候选池继续使用高流动性/市值/换手过滤，市场宽度改用独立的非 ST、非北交所、上市满一年且具备足够 K 线的宽样本。`071` 滚动窗口验证全部通过：7 个窗口通过 7 个，最低年化收益约 `9.31%`，最低 Sharpe 约 `1.52`，最深窗口回撤约 `-6.97%`，最低窗口 Risk-On 天数 `38`。`072` 在新宽度口径下三年完整窗口继续通过：总收益约 `68.92%`，年化约 `19.11%`，最大回撤约 `-4.16%`，Sharpe 约 `2.40`。`073/074` 的 2 倍/3 倍成本压力也继续通过目标硬门槛。因此当前可执行基线更新为“独立市场宽度样本 + 13.5% 建仓上限”的组合策略。

`075` 至 `077` 增加成交现实性压力测试。`077` 只加入买卖各 `0.1%` 滑点，目标硬门槛仍通过：总收益约 `70.92%`，最大回撤约 `-5.14%`，Sharpe 约 `2.42`，估算滑点成本约 `4629`。`076` 在同样滑点下把止损跳空低开改为按开盘价成交，组合总收益仍有约 `60.36%`，最大回撤约 `-6.02%`，但成交标的后 10 最差收益扩大到约 `-11.63%`，尾部亏损/回撤门槛失败。`075` 再加入 `9.5%` 涨停附近禁止买入后，拦截 `13156` 个信号，收益降至约 `-1.51%`，说明一刀切涨停禁买过强。下一轮默认方向应是隔夜跳空尾部风险过滤，而不是粗暴禁止所有强势涨停附近信号。

`078` 至 `080` 继续拆解跳空尾部。`078` 把买入日高开限制到 `5%`，总收益只有约 `25.05%`，尾部仍破 `10%`。`079` 禁止近 60 日出现超过 `3%` 隔夜低开的标的，尾部违规从 `5` 个降到 `1` 个，但总收益只有约 `15.55%`。`080` 放宽到 `4%` 后，总收益约 `27.42%`，并出现约 `-31.28%` 的新尾部样本。结论：历史跳空特征可用于诊断，但不适合单独硬过滤；下一轮应研究入场后保护或组合层隔夜暴露控制。

`081` 至 `082` 验证“收盘信号、次日开盘执行”的替代成交时点。`081` 在次日开盘低于信号收盘 `3%` 或低于止损时取消订单，结果总收益约 `22.73%`，最大回撤约 `-10.72%`，尾部最差约 `-20.99%`。`082` 要求次日开盘不低于信号收盘价，取消订单增至 `192` 个，但总收益只有约 `5.57%`，尾部最差约 `-21.50%`。结论：推迟入场会破坏横截面择强收益结构，也不能修复跳空止损尾部；后续应转向组合层隔夜风险预算或入场后动态减仓。

`083` 至 `084` 继续验证入场后保护和买入日复合硬过滤。`083` 在开仓后 2 个持有日内若收盘跌破开仓日低点则退出，只触发 `7` 次，组合总收益降至约 `51.64%`，尾部最差仍约 `-11.63%`，说明收盘级早期保护无法处理隔夜直接跳空到止损下方的样本。`084` 同时限制买入日高开不超过 `5%`、振幅不超过 `7%`、日内涨幅不超过 `4.8%`，结果买入风险过滤拦截 `13515` 个信号，组合总收益只有约 `7.73%`，还引入 `603773.SH` 约 `-23.69%` 的新尾部。结论：继续收紧买入日形态阈值不进入当前基线；下一轮应转向事件/行业隔夜风险标签、跳空后再入场冷却或同类行业熔断。

`085` 验证跳空止损后的再入场冷却和同类行业熔断：跳空止损后全市场暂停新开仓 `3` 天、同行业冷却 `20` 天、同标的冷却 `60` 天。该规则触发全市场/行业/标的冷却各 `19` 次，分别拦截 `945`、`7303`、`493` 个信号；组合总收益仍有约 `44.34%`，最大回撤约 `-5.42%`，但成交标的后 10 最差仍约 `-11.63%`，尾部亏损/回撤违规仍有 `4` 个。结论：事后冷却不能修复首次隔夜跳空尾部；下一轮应研究开仓前或持仓过夜前生效的事件/行业隔夜风险标签、隔夜仓位预算或更真实的涨跌停/停牌成交模型。
