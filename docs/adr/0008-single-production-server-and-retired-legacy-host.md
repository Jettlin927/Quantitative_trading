# 单一生产服务器与旧服务器退役

> 2026-08-05 更新：公共数据 Worker 已由
> [ADR 0010](0010-us-first-workbench-and-retired-legacy-data-paths.md) 退出目标运行拓扑。
> 本文关于单一生产服务器和旧服务器退役的决定继续有效。

状态：已接受（2026-08-03）

## 决策

- 原 `quant-trading-new` 服务器定义为唯一生产服务器，统一使用逻辑角色和 SSH
  别名 `quant-trading-prod`。
- PostgreSQL、API、研究 Worker、前端和 canonical 研究工件只在
  `quant-trading-prod` 运行，并以该服务器的现场读回为生产事实。
- 原 `quant-trading-server` 服务器退出本系统，不再承担生产、前端、后端、同步、
  研究、灾备或回滚角色，也不得作为数据权威。
- 不采用前端与后端跨服务器拆分。当前前端是轻量只读静态服务，与 API 同机部署
  可以保留同源反向代理、loopback 监听和单一发布验收边界。
- 用户访问继续只通过指向 `quant-trading-prod` 的 SSH 隧道；不得因角色调整开放
  公网应用端口。

## 退役事实

2026-08-03 已停止并删除旧服务器上的本项目 PostgreSQL、API、数据 Worker 和前端
容器，同时删除对应 Compose 网络、镜像、构建缓存和全部 4 个未挂载 Docker
volume。被删除的 volume 包括历史 PostgreSQL 数据、研究工件和前端依赖，删除不可
恢复。旧服务器不再监听本项目的 `5432`、`18000` 或 `15173` 端口。

旧服务器上的源码目录和其他普通文件不在本次 Docker 清理范围内，但它们不构成
灾备，也不得重新接入生产。

## 取代关系

本决策结束 ADR 0005 中的双服务器迁移和旧服务器回滚观察阶段。ADR 0005 继续作为
历史迁移方法保留，但不再描述当前生产拓扑。

## 生产门禁

`quant-trading-prod` 上的部署、数据库 migration、数据修复、凭据变更和删除操作仍
按仓库现有授权与验收规则执行。服务器角色确定不代表自动授权这些操作。
