# 历史研究导入是来源记录，不是研究批准

统一研究档案需要容纳治理合同建立前的可信报告、运行和 legacy 档案，但这些历史对象没有当前合同要求的精确计划哈希批准。系统以独立的 `historical_import` 来源身份保存它们，只关联运行 ID、策略 ID、成功状态、结果指纹、复现键和代码提交均一致的既有运行，并原样保留已有结论；该身份不能授权新运行、补跑或把旧 `status=ok` 翻译成研究结论。历史正式研究保持终止态，数据库拒绝把新运行挂到该来源；统一发布记录保持 `pending`，只有后续生产迁移及 Issue、API、前端对同一版本的读回全部完成，才能按发布合同晋升。原生正式研究仍只能由用户对冻结计划的精确哈希批准。
